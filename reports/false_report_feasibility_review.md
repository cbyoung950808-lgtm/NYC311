# 허위·오류 가능 신고 검토 업무의 타당성 검토

> 반복 신고의 빈도·간격·장소·유형·접수 경로·종결 문구를 분석해 「추가 확인이 필요한 신고」를 찾고 담당자의 검토·중복 처리 부담을 줄일 수 있는가?

- **작성**: 2026-11-28
- **성격**: 기능 구현이 아닌 **추진 여부 검토**. 대시보드·모델·배포는 만들지 않았다.
- **검토 자료**: 프로젝트 문서(`docs/preprocessing.md`, `docs/data_catalog.json`), 보고서(`data_quality_report.md`, `repeat_address_report.md`, `rereport_report.md`, `poi_report.md`, `repeat_profile_report.md`, `resolution_playbook_report.md`), 전처리 자료 `data/processed/311_requests_clean.parquet`(읽기 전용 소규모 집계)
- **보존**: 원자료·전처리 결과·기존 보고서·대시보드는 바꾸지 않았다.
- **용어**: 이 문서에서 「특이 패턴」은 통계적으로 드문 접수 모습일 뿐이며, 「허위 신고」를 뜻하지 않는다.

---

## 판단: 허위 판별보다 다른 업무 목표로 전환 권고

- **바꿀 목표**: 「허위 신고 판별」 대신 **「같은 사안의 중복·연속 접수를 한 묶음으로 연결하고, 기록 정보 오류를 보완하는 검토 보조」** 로 전환할 것을 권한다.
- **허위·고의 판단은 현재 자료로 불가능하다.** 신고자 식별 정보, 신고 내용 원문, 현장 확인 결과가 없다. 그리고 「위반 없음」 종결은 정상 신고에서도 흔하다(경찰 주거 소음의 84.0%).
- **사업 필요성 미확인.** 허위 신고의 규모나 그로 인한 업무 비용을 보여 주는 자료가 프로젝트에 없다.
- **바꾼 목표도 조건이 있다.** 기관에서 「기록 한 건마다 처리하는 부담」이 실제로 있는지 먼저 확인해야 한다. 그 뒤에야 과거 자료로 제한적인 시범 검토를 할 수 있다.

## 1. 확인된 사실과 확인되지 않은 가정

### 확인된 사실

**보유 자료와 관측 단위**
- 처리된 자료는 58개 열이고, 관측 단위는 「311 접수 기록 1건」이다.
- 자료에 **없는 것**:
  - 신고자 식별 정보
  - 신고 내용 원문(`problem_detail`, `additional_details`는 고정 분류값)
  - 발생 시각(`created_date`는 접수 시각)
  - 현장 방문 여부와 결과를 담은 별도 항목
- 종결 결과는 기관이 쓴 정형화된 종결 문구(`resolution_description`)로만 알 수 있다.
- 위치는 **신고된 주소**이며 발생원이 아니다(`place_centred_report.md`).
  - 주소 비교 키(`address_key`)는 공백·대소문자만 통일한다. 약어(ST/STREET)는 합치지 않는다.
  - 호실(세대) 정보는 없다.

**짧은 간격 반복** (번지 주소 기록 3,815,280건 기준, 중복 의심 제외)

| 지표 | 값 |
|---|---:|
| 같은 주소·유형의 앞 기록과 **같은 초** | 108,349건 (4.48%) |
| 앞 기록과 **60초 안** | 170,783건 (7.07%), 주소 32,306곳 |
| 60초 안 기록 중 상위 10개 주소 / 상위 100개 주소 | 36,578건(21%) / 47,728건(28%) |
| 집중 주소(655 East 230th St)를 빼면 60초 안 비율 | 5.96% |

- **같은 초 기록은 대부분 HPD의 주택 수리 신고**다(비위생 상태·페인트·배관·문창, 전화·온라인).
  - 한 번의 접수가 증상별로 여러 기록으로 나뉜 모습이다(예: 「벽 균열」 + 「떨어지는 회반죽」, 「연기 감지기」 + 「일산화탄소 감지기」).
  - 같은 초 기록 중 세부 유형·추가 설명까지 앞 기록과 같은 경우는 11.0%뿐이다.
  - **기록이 만들어지는 방식**이며 신고자의 행동이라고 볼 근거가 없다.
- **1~60초 간격은 경찰(NYPD) 주거 소음 + 모바일 앱이 가장 많다**(30,269건).

**접수 경로별 60초 안 비율**

| 경로 | 전체 | 상위 100개 주소 제외 |
|---|---:|---:|
| 전화 | 11.27% | 11.16% |
| 모바일 앱 | 7.29% | **1.86%** |
| 온라인 | 5.74% | 4.83% |
| 경로 미기재 | 3.07% | 2.99% |

- 모바일 앱의 짧은 간격 접수는 **몇몇 주소에 몰려 있다**.
- 전화의 높은 비율은 주소를 빼도 유지된다. 한 통화에서 여러 기록이 생기는 방식과 관련 있어 보인다(확인 필요).

**종결 문구** (`resolution_playbook_report.md`의 문구 분류)

| 대상 | 「위반·문제 없음」 비중 |
|---|---:|
| 전체 신고 | 47.0% |
| 경찰 주거 소음 (집중 주소 제외) | 84.0% |
| 집중 주소 | 98.7% |

- 집중 주소의 종결 문구는 대부분 「경찰이 출동했으나 범죄 위반의 증거 없음」이다. 이는 경찰 주거 소음 전체에서도 가장 흔한 문구다.
- 집중 주소의 기록 47,105건은 「같은 날·장소·유형·세부 유형」 묶음으로는 157개다.
- 종결 시각이 **같은 초인 기록이 20건씩** 반복된다. 일괄 종결로 보이며, 기록마다 출동했는지는 이 자료로 알 수 없다.

**이미 있는 중복 처리**
- 기관이 「중복」으로 종결한 기록(`flag_agency_duplicate`)이 183,084건(4.6%)이다. HPD 119,569건, 환경보호국 43,058건, 교통국 20,166건.
- 「같은 날·장소·유형·세부 유형」 묶음에 2건 이상 들어간 기록이 전체의 24.2%다.
- 요청 번호만 다르고 나머지가 같은 기록 1,791건은 이미 기본 분석에서 빠져 있다.

**기록 품질 관련 수치** (`data_quality_report.md`, 전처리 요약)
- 위치 없음 82,954건, 자치구 없음 3,794건, 우편번호로 채운 자치구 265건
- 커뮤니티 보드 번호와 자치구 불일치 2,752건(`events_report.md`)
- 상태가 Closed가 아닌데 종료일이 있음 19,237건, 종료가 접수보다 빠름 1,371건, 종료 = 접수 시각 62,788건
- 접수 경로 「UNKNOWN」 332,035건
- 다음 변화가 「특이 패턴」처럼 보일 수 있다.
  - 유형 이름 변경(2026-07-28~29)
  - 노숙 거처 담당 기관 이관(2026-10)
  - HPD가 난방 신고를 열어 두는 기록 방식의 연도별 변화
  - 지난해 파일의 늦은 추출 시점

**편향 관련**
- 반복 신고 주소를 가장 잘 가르는 특성은 세대 수다(100세대 이상이 6~19세대보다 약 2.9~3.5배, `repeat_profile_report.md`).
- 공공임대주택(NYCHA)의 주택 관리 신고는 311 자료에 거의 없다(`nycha_report.md`).

### 확인되지 않은 가정

- 허위·고의 신고가 실제로 많으며 업무 비용을 만든다.
- 기관이 기록 한 건마다 별도로 배정·출동·검토한다(묶어 주면 부담이 줄어든다).
- 짧은 간격의 연속 접수가 한 사람에게서 나온다.
- 「위반 없음」 종결이 실제로 문제가 없었음을 뜻한다.

## 2. 문제와 목표의 타당성

| 질문 | 답 |
|---|---|
| 줄이려는 비용·피해는? | 같은 사안을 여러 기록으로 처리하는 시간, 불필요한 출동. **어느 것도 프로젝트 자료로 크기를 잴 수 없다.** |
| 허위 신고가 중요한 문제라는 증거는? | **없음.** 「위반 없음」 종결은 정상 신고에서도 흔하고, 허위로 확인된 사례가 없다. → **사업 필요성 미확인** |
| 반복·중복·입력 오류·확인 불가·사실과 다름·고의 허위를 구분할 수 있나? | 반복과 일부 중복, 일부 입력 오류만 가능. 확인 불가·사실과 다름·고의는 구분할 수 없다. |
| 담당자가 결과를 받고 할 수 있는 행동은? | 관련 기록을 묶어서 보기, 기록 정보 보완. 신고 차단·불이익은 근거가 없어 전제하지 않는다. |
| 기존 연결·보완 절차로 해결되나? | 일부는 이미 된다(기관의 중복 종결 4.6%, 일괄 종결 흔적). 남은 부담이 있는지부터 확인해야 한다. |

## 3. 작업별 가능 여부

| 작업 | 판정 | 근거 |
|---|---|---|
| 특이한 반복 접수 패턴 탐지 | **현재 가능** | 주소·유형·접수 시각·경로로 간격과 몰림을 셀 수 있다. 결과는 「특이함」이지 허위가 아니다. |
| 동일 사안 중복 가능성 확인 | **조건부 가능** | 같은 날 묶음과 기관의 중복 종결이 있다. 다만 HPD 증상별 분할, 큰 건물의 여러 세대를 구분하는 규칙을 먼저 정하고 표본 검토로 검증해야 한다. |
| 주소·시간·분류 정보 오류 탐지 | **조건부 가능** | 자치구 충돌, 위치 없음, 상태·날짜 모순, 이름 변경은 찾을 수 있다. 어느 값이 맞는지는 기관 원부와 대조해야 한다. |
| 현장 확인이 필요한 사례 선정 | **추가 자료 필요** | 출동·방문 기록과 결과가 없다. |
| 신고 내용이 사실과 다른지 판단 | **현재 부적합** | 내용 원문과 현장 결과가 없고, 「위반 없음」은 정상 신고에서도 흔하다. |
| 신고자의 고의성 판단 | **현재 부적합** | 신고자 정보와 의도를 알 수 없다. 「특정 주민·신고자 추정 금지」라는 프로젝트 원칙과도 맞지 않는다. |

## 4. 탐지 신호와 대안 설명

| 신호 | 실제로 재는 것 | 허위·오류와 관련될 수 있는 이유 | 정상 신고에서도 나타나는 이유 | 기록 방식으로 설명되는가 | 판단에 필요한 확인 |
|---|---|---|---|---|---|
| 짧은 간격 반복 | 같은 주소·유형의 앞 기록과의 시간 | 같은 사람의 연속 제출 가능성 | 여러 세대의 신고, 문제 지속 | **예**: 같은 초 기록은 대부분 HPD 증상별 분할 | 제출자 수(가명 처리한 수만), 접수 내부 기록 |
| 반복 빈도 | 주소당 기록 수 | 소수 주소에 지나치게 몰림 | 세대 수, 지속되는 실제 문제 | 일부(분할 기록, 일괄 종결) | 세대 수로 나눈 비교, 기관 처리 기록 |
| 시간 간격의 규칙성 | 간격 분포 | 기계적 반복 | 소음·난방처럼 지속되는 문제 | 일괄 등록·일괄 종결 시각 | 접수 시스템 기록 |
| 특정 시간대 몰림 | 시간대별 비중 | 일정한 패턴의 제출 | 소음은 원래 밤에 몰림 | 자정 기록 일부(교통국·보건국 약 0.9%) | 같은 유형의 시간 분포와 비교 |
| 지역 추세와의 차이 | 주변·같은 유형 대비 비율 | 주변과 동떨어진 급증 | 행사·날씨·건물 문제 | 이름 변경·기관 이관 시점 | 날씨·행사·기록 변경 대조 |
| 종결 뒤 재접수 | 종결 후 N일 안 같은 주소·유형 신고 | 결과 불만의 반복 | 미해결, 다른 세대, 새 문제 | 「중복」 종결 뒤가 가장 높음(활발한 주소의 표시) | 실제 해결 여부, 세대 정보 |
| 접수 경로 몰림 | 한 경로의 비중 | 같은 계정·기기의 반복 | 그 주소 주민이 주로 앱을 씀 | 경로 미기재 33만 건 | 경로별 제출자 수(가명 처리한 수만) |
| 「위반 없음」·「출입 실패」·「중복」 종결 | 기관 종결 문구 | 사실과 다른 신고일 수 있음 | 도착했을 때 소음이 그침, 출입이 막힘, 여러 세대 신고 | 정형 문구, 일괄 종결 | 현장 기록 원부 |

## 5. 필요한 최소 추가 자료

공식 출처에서 직접 확인한 것은 없다. 아래 보유처와 확보 가능성은 **추정**이다.

| 자료 | 필요한 판단 | 보유처 (추정) | 연결 키·시점 | 권한·개인정보 |
|---|---|---|---|---|
| 기록 한 건당 처리 여부·시간(배정, 출동, 일괄 종결) | 줄이려는 부담의 크기 | 해당 기관(NYPD, HPD 등) | 요청 번호, 같은 기간 | 내부 업무 자료 |
| 같은 주소·시간대의 서로 다른 제출자 **수** | 한 사람의 연속인지 여러 세대인지 | 311 운영 부서 | 요청 번호 | 신원은 받지 않고 집계 수만 요청 |
| 접수 시점의 중복 연결 기록 | 이미 묶이는지 | 311 운영 부서 | 요청 번호 | 내부 |
| 현장 확인 결과 원부 | 사실 여부 | 해당 기관 | 요청 번호 또는 기관 사건 번호(연결 가능 여부 확인 필요) | 내부 |
| 기관 자체의 「근거 없음·허위」 분류 기준과 건수(있다면) | 문제의 규모 | 해당 기관 | - | 있는지부터 확인 필요 |

**정답 없이 평가하는 방법 (담당자 표본 검토)**
- **표본**: 표시된 묶음과 표시되지 않은 묶음을 유형·자치구·건물 규모·접수 경로별로 나눠 뽑는다.
- **검토 방식**: 검토자 2명 이상이 서로 결과를 모른 채 따로 판정한다.
- **판정 범주**: 같은 사안 중복 / 다른 세대·다른 문제 / 기록 정보 오류 / **판단 불가**. 「허위」는 범주로 두지 않는다.
- **측정할 것**:
  - 검토자 간 일치도(카파 등)
  - 「판단 불가」 비율
  - 표시된 묶음 중 실제로는 다른 문제였던 비율(정상 신고를 잘못 묶은 비율)
  - 표시되지 않은 묶음 중 놓친 중복 비율

---

## 6. 기대 효과와 잘못된 판단의 비용

**기대 효과 (규모 미확인)**
- 연속·중복 기록을 한 묶음으로 보여 주면 담당자가 같은 사안을 여러 번 여는 일이 줄 **수 있다**(예: 집중 주소 47,105건 → 같은 날 묶음 157개).
- 다만 기관이 이미 일괄 종결한다면 줄어들 부담이 작을 수 있다. 그래서 **절감 효과를 숫자로 제시하지 않는다.**
- 정보 오류(자치구 충돌, 상태·날짜 모순) 보완은 위험이 낮고, 분석 품질에도 바로 도움이 된다.

**잘못된 판단의 비용**
- 큰 건물의 여러 세대가 같은 문제로 신고한 것을 「의심」으로 표시할 위험이 있다. 난방·비위생 같은 건물 단위 문제에서 특히 그렇다.
- 앱·전화 사용자와 특정 지역이 더 자주 표시되는 편향이 생길 수 있다. 덜 신고하는 곳(NYCHA 등)은 처음부터 보이지 않는다.
- 표시된 신고의 대응이 늦어지면 실제 위험을 놓칠 수 있다(난방·가스·안전 유형).
- 검토 대상이 늘면 사람이 확인할 일이 오히려 늘 수 있다.
- 「의심 표시」가 알려지면 주민이 신고를 꺼리게 될 수 있다.

## 7. 추진 여부를 정할 기준

**추진 조건 (모두 충족)**
1. 기관이 「기록 한 건마다 처리하는 부담」이 실제로 있다고 확인하고, 그 크기를 잴 수 있다.
2. 과거 자료 표본 검토에서 검토자들이 미리 정한 일치도 기준에 도달한다. 기준값은 기관과 함께 정한다.
3. 표시된 묶음이 큰 건물이나 특정 접수 경로에 지나치게 치우치지 않는다. 세대 수와 경로를 맞춘 뒤에도 확인한다.
4. 결과를 차단·불이익이 아니라 **묶음 보기와 정보 보완에만** 쓴다는 운영 원칙에 동의한다.

**중단 기준 (하나라도 해당)**
- 처리 부담이 확인되지 않거나, 기관이 이미 같은 방식으로 묶어 처리한다.
- 표시된 묶음의 대부분이 HPD 증상별 분할이나 큰 건물의 여러 세대로 판명된다.
- 「판단 불가」가 다수이거나 검토자 간 일치도가 기준에 못 미친다.
- 대응 지연이나 신고 위축 신호가 보인다.
- 결과를 신고 차단이나 신고자 판정에 쓰자는 요구가 나온다.

## 8. 최소 규모 시범 검토안 (목표를 바꾼 경우에만, 운영 시스템과 분리)

1. **대상**: 과거 자료 한 달, 두세 개 유형(예: 경찰 주거 소음, HPD 비위생).
2. **만드는 것**: 「같은 주소·유형·경로의 짧은 간격 묶음」과 「정보 모순 기록」 목록을 읽기 전용으로 만든다.
   - HPD의 같은 초 분할 기록은 미리 한 묶음으로 처리한다.
   - 「허위」라는 이름은 쓰지 않는다.
3. **검토**: 5절의 표본 검토 방법으로 담당자 2명 이상이 판정한다.
4. **판단**: 7절 기준으로 계속할지, 중단할지 정한다.

**이 단계에서 먼저 확인할 것**: 기관이 정말로 기록 한 건마다 처리하는지, 그 부담이 얼마인지. 이것이 확인되기 전에는 무엇을 만들지보다 **추진할지 자체를 정할 수 없다.**
